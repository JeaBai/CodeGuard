# 项目管理五阶段框架 — 完整参考

> 核心理念：用小成本验证方向、用明确标准定义质量、用高频检视防止跑偏、用外部视野打破回音壁。

---

## 第一阶段：项目启动前 — 判断「值不值得做」

**目标**：用最少成本验证方向，避免资源投入后发现走错路。

**产出物**：《项目可行性评估报告》

### 🔍 市场需求调研

| 2 | 市场上已有哪些解决方案？它们的优缺点分别是什么？ | 竞品分析，找差异化空间 | |

## 跨阶段能力矩阵

### 决策类型速查

| 决策类型 | 对应阶段 | 关键问题 | 决策方法 |
|----------|----------|----------|----------|
| 方向决策 | 阶段一 | 值不值得做？ | SWOT + 机会成本分析 |
| 规划决策 | 阶段二 | 怎么做？多快做完？ | 里程碑倒推 + 风险矩阵 |
| 纠偏决策 | 阶段三 | 走偏了吗？如何修正？ | 偏差分析 + 范围裁剪 |
| 续投决策 | 阶段四 | 要不要做V2.0？ | ROI评估 + 用户验证 |
| 转向决策 | 阶段五 | 方向要不要微调？ | 信号强度评估 |

### 应急响应清单

| 触发条件 | 应急动作 |
|----------|----------|
| 进度延期 > 10% | 范围裁剪：砍掉非MVP功能 |
| 进度延期 > 20% | 重新评估：是否拆分交付 |
| 进度延期 > 30% | 止损决策：暂停or重组资源 |
| 发现致命风险 | 立即上报，暂停相关开发 |
| 竞品发布重大更新 | 24小时内完成影响评估 |
| 关键技术栈宣布EOL | 启动技术迁移评估 |
