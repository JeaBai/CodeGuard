# 项目管理检查清单 — 快速索引

## 阶段一：可行性检查清单

- [ ] 明确了目标用户画像
- [ ] 确认用户最痛的1-3个问题
- [ ] 完成了竞品分析（至少3个竞品）
- [ ] 找到了差异化切入点
- [ ] 验证了付费意愿（至少访谈5个潜在用户）
- [ ] 评估了市场规模和增长趋势
- [ ] 识别了资源瓶颈
- [ ] 评估了能力匹配度
- [ ] 完成了MVP范围定义
- [ ] 识别了TOP3风险
- [ ] 定义了止损底线
- [ ] 完成了合规预检
- [ ] 综合得分 ≥ 15/20

## 阶段二：规划检查清单

- [ ] 定义了项目的「高质量」标准
- [ ] 设定了最低验收标准
- [ ] 明确了非功能需求
- [ ] 定义了用户体验标准
- [ ] 确定了最终交付日期
- [ ] 倒推出了各阶段时间节点
- [ ] 区分了MVP功能和V2.0功能
- [ ] 明确了每个里程碑的交付物和验收人
- [ ] 设定了偏差预警机制（10%阈值）
- [ ] 完成了技术方案对比分析
- [ ] 验证了学习成本与时间预算匹配
- [ ] 评估了新技术的必要性（非新鲜感驱动）
- [ ] 评估了长期维护成本和可用资源

## 阶段三：执行检查清单 — 每日

- [ ] 记录了今日完成事项
- [ ] 对比了计划进度（提前/正常/滞后）
- [ ] 识别了当前阻塞点
- [ ] 制定了阻塞清除计划

## 阶段三：执行检查清单 — 每周

- [ ] 评估了本周里程碑完成概率
- [ ] 决定了是否需要范围裁剪
- [ ] 检视了精力分配（高价值 vs 琐事）
- [ ] 复盘了时间利用效率
- [ ] 检查了新模块的边界覆盖
- [ ] 核实了核心路径测试覆盖率
- [ ] 更新了技术债务清单
- [ ] 整理了用户反馈中的重复问题
- [ ] 建立了定期站会与干系人沟通机制
- [ ] 确认了质量红线未被突破
- [ ] 扫描了竞争对手动态
- [ ] 浏览了GitHub Trending
- [ ] 评估了方向是否需要微调

## 阶段四：复盘检查清单

- [ ] 量化了目标达成率
- [ ] 列出了做对的可复用经验
- [ ] 列出了做错的需避免教训
- [ ] 计算了实际时间 vs 预估时间的偏差
- [ ] 分析了偏差最大的环节及原因
- [ ] 整理了超出预期的反馈
- [ ] 整理了低于预期的反馈
- [ ] 评估了V2.0的价值和依据
- [ ] 沉淀了可复用代码/模板/流程
- [ ] 记录了踩坑清单
- [ ] 更新了工具链
- [ ] 提炼了核心经验（一句话）

## 阶段五：视野跟踪清单 — 每周30分钟

- [ ] 浏览GitHub Trending（领域相关）
- [ ] 搜索新的AI工具/模型
- [ ] 检查主流框架/平台更新
- [ ] 浏览行业头部企业动态
- [ ] 阅读至少一篇反对既有观点的内容
- [ ] 浏览目标用户社区最新讨论
- [ ] 搜索新竞品或替代方案
- [ ] 分析用户评价中的高频词
- [ ] 评估改进方向
