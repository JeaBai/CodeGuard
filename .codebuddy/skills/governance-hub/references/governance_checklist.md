# 发布前治理检视细则与通告模板（governance-hub v0.1.0）

> 发布前五问：需求有源 / 变更有界 / 数据有悔 / 成本有谱 / 通告有达。
> 与 project-manager 的 `enterprise-governance-checklist.md` 关系：本文件为**发布时点**的精简 Gate 版；那份为**过程周期**的完整词条版。两者互补不重复。

## 一、五问检视细则

### 1. 需求有源（D9）
- 统计本版 PR 关联需求 ID 的比例（目标 ≥95%；CI 可由 GitLab Push Rules / PR 标题 Action 强制，B-47/B-48）。
- 无源变更逐条登记理由（hotfix/技术债/安全修复可豁免，但须留痕）。
- 成长型及以上：核对 AC 是否在开发前以 Gherkin 固化（防止 AI 按模糊需求自由发挥）。

### 2. 变更有界（D12）
- 检查 `openapi.yaml` 等契约文件 diff：oasdiff breaking 结果（CI：openapi-contract 模板）。
- 存在破坏性变更时，确认每个下游团队已在 MR 中回复确认（Terrateam 事故：GitHub API 204→200 静默变更直接击穿生产，已核验）。
- 对外部 API 消费者：确认通告 SLA（提前 N 天 + 迁移指南）已履行（tianpan.co：一次重构影响 10,000 学区，$2M+ 合同受威胁）。

### 3. 数据有悔（D10）
- CI db-migration-guard 全绿（空 downgrade / DELETE·UPDATE 无 WHERE / TRUNCATE 已拦截）。
- 大表变更确认在线 DDL 方案；涉及回填的迁移已准备对账 SQL。
- GitLab 2017 教训：五种"备份"同时失效——回滚方案必须**演练过**才算存在（B-2/B-8，高度可信）。

### 4. 成本有谱（D11）
- 新增/变更工作负载全部声明 requests/limits（CI：finops-quota 模板）。
- 预估本版资源变化（副本数/存储/带宽）对月度成本影响；超基线 ±10% 需说明。
- 依据：Datadog 83% 容器成本与空闲资源相关（已核验）；CNCF：超支主因过度配置（已核验）。

### 5. 通告有达（D12）
- Release Notes 草稿已由 `release_notes_draft.py` 生成并完成两步润色（迁移指南 + 业务版转换）。
- 双轨通告已发送至渠道矩阵全部渠道；核心下游已获得人工确认回执。

## 二、双轨通告模板

### 技术版（工程师/下游团队）
```markdown
【发布通告】<服务名> <版本> — <YYYY-MM-DD HH:mm 生效>
## 变更清单
- API 变更：<新增/修改/废弃端点清单>
- 破坏性变更：<明细> | 迁移指南：<链接> | 最晚迁移截止：<日期>
- 数据库变更：<迁移脚本编号> | 回滚方案：<downgrade 已演练/对账 SQL>
## 回滚预案
- 触发条件：<错误率/延迟阈值> | 回滚方式：<Argo 自动/revert> | 预计耗时：<N 分钟>
## 负责人
- 发布：<@owner> | 值班：<@oncall> | 下游对接：<@liaison>
```

### 业务版（PM/运营/客服）
```markdown
【功能更新】<一句话用户价值> — <生效日期>
## 你将看到的变化
1. <用户可感知变化 1>
2. <用户可感知变化 2>
## 需要配合的动作
- <无 / 重新登录 / 清理缓存 / 客服话术更新（附链接）>
## 咨询入口
- <群/邮箱/oncall>
```

## 三、渠道矩阵（按体量）

| 体量 | 技术版渠道 | 业务版渠道 | 回执要求 |
|------|-----------|-----------|---------|
| 初创 | 群消息 | 群消息 | 无 |
| 成长型 | Slack/钉钉 webhook + MR 评论 | 公告页 + 群消息 | 下游组长确认 |
| 大型 | 公告页 + 邮件列表 + webhook | 公告页 + 双周同步会 | 核心下游回执 |
| 跨国 | 多时区分批通告 + 分级邮件 | 区域化公告 | 区域负责人回执（监管行业加审批流） |
