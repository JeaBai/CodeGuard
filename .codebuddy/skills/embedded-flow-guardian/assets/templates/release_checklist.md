# 发布准出清单（Release Exit Checklist）

> **本清单是「放行依据」，不是「检查项罗列」。每一条都必须有明确的通过判据。**
> 填写纪律：`☐ 未检查` / `☑ 通过` / `✗ 不通过（须说明）` / `N/A 不适用（须说明理由）`
>
> 原则：**证据应随开发持续产生，而不是发布前补写。**
> 若某项证据是发布前临时补的，请在备注里写明——这不是禁止，而是要让风险可见。

### 附：本清单的设计依据（可引用）

- **门禁只拦「快且确定」的信号**；慢且易抖的 HIL 与 soak 测试应移到定时流水线，否则「红=噪声」，门禁会沦为剧场。
- **增量优于绝对**：用「新代码覆盖率」而非「全仓库覆盖率」——后者会在历史代码上永久卡住流水线。
- **覆盖率必须配套**：只调用不断言的测试可以做到 100% 覆盖率、0% 变异得分。
- **黑匣子优先级很高**：航空业 NFF（无法复现故障）比例达 20–60%，成因清单里「无法复现环境」与「缺乏故障日志」排最前。**别等炸机后才后悔没装。**
